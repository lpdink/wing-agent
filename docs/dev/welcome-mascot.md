# 开屏海鸥（welcome mascot）

欢迎屏的那只海鸥：待机是站姿 chibi，agent 干活时切成飞行扇翅 —— "它在飞" = "它在干活"。
代码在 `crates/wing/src/ui/welcome/`（`art` 数据 · `sprite` 渲染 · `motion` 规划 · `wordmark` 大字 · `mod` 组装）。

## 数据形态：字母网格

与 dsh 的像素鲸鱼同构：每帧是 `&[&str]`，一个字符 = 一个**像素**（不是终端格），
`.` 透明，其余字母是调色板键（`sprite::brand`）：

| 字母 | 暗底 | 亮底 | 用途 |
|------|------|------|------|
| `O` | `#1B2338` 深藏青 | 同左 | 描边（不是纯黑；亮底靠它撑剪影） |
| `W` | `#F7F9FC` 羽白 | `#C9D3E2` 浅蓝灰 | 羽色（白底上白羽等于透明） |
| `G` / `S` | `#C9D2E0` / `#8E9BB0` | `#AAB7C9` / `#7F8EA8` | 浅灰 mantle·折翼 / 石板灰翼下缘 |
| `D` | `#3A4763` | `#4A5878` | 深石板翼尖·尾尖 |
| `B` / `M` | `#F5A93C` / `#C77E22` | 同左 | 琥珀喙·脚 / 暗面 |
| `E` / `H` | `#141C33` / `#FFFFFF` | 同左 | 眼 / 眼神光 |
| `A` | 主题 accent | 同左 | 唯一跟主题走的字母（点缀预留） |

羽色两套由 `ThemePalette::appearance` 选择（`crates/wing/src/ui/welcome/sprite.rs::brand`），
`examples/export_logo.rs` 的 `banner-light.svg` 用亮底那套。

**品牌色固定、不跟主题走**：海鸥之所以是海鸥靠的就是这身颜色；跟主题呼吸的只有
`A`、羽色两套（暗底白羽 / 亮底浅蓝灰）与 wordmark 的渐变方向（暗底冰→accent，
亮底 accent→深，见 `ThemePalette::appearance`）。

渲染是半格：一个终端格装上下两像素，上=前景、下=背景；只画半格的格子只设前景
（给 `▄` 配背景会把透明的上半填成对面那半的颜色）。见 `sprite::lines`。

## 姿态与动作族

`motion::Motion` 是纯 deadline 状态机（无定时器、无 RNG：jitter 由内部计数器派生，
测试可复算）。语义借自 dsh 的 `whaleIdle.ts`：**每个动作族独立一条平面**
（眨眼 / 抖翅 / 跳各管各的 deadline），"眨眼落在抖翅中途"天然成立。

* 待机（`Pose::Perched`）：`Idle / Blink / Flutter1 / Flutter2` + `lift`
  （0 站定 / 1 呼吸 / 2 跳；抬升 = 标准姿势整帧上移 1 或 2 像素行，不额外存帧）；
  **呼吸是常驻平面**（每 ~1.9s 抬半格 ~320ms）—— 没有它待机就是"每几秒一闪的
  静态图"，用户实测原话"等了半天才看到动画"。节奏常数刻意比 web 宠物密
  （dsh 鲸鱼同款教训：终端 settled header 上按 web 节奏会 visibly stalls）；
* 干活（`Pose::Flying`）：`FLY_0..FLY_5` 六帧扇翅循环，90ms/帧；
* `working` 翻转时重新播种对面那档的节奏 —— 落回站姿不会"一落地就连眨三下"；
  欢迎屏从视口外回来时同样重播（`Motion::resume`），否则四个平面同时到点，
  回屏第一帧会叠成"眨眼 + 跳 + 呼吸"。
* **序列里不许有相邻同值步**（`BREATH_SEQ` / `HOP_SEQ` 都是单拍）：那种 deadline
  不改变姿态，是白醒 + 白重绘（曾经两个平面写成 `[1, 1]`，实测 20.5% 的 tick 空转）。

两个姿态在 header 里对齐到同一终端行数（`ART_TERM_ROWS = 13`，矮的那个顶部补透明），
姿态切换不跳版。盒子比站姿网格高两像素行（`PERCHED_TOP_PAD`）—— 抬升是把整帧上移，
没有头顶余量就会裁掉头冠，读起来像被压扁而不是跳起来。

## 名牌右列：字号档位 + 信笺

海鸥右边那一列 = **wordmark** + **名牌**（身份 / 分节线 / 键位 / tip / 入口）。
它像一张**信笺**（logo 下面是文字），不像一张表 —— 早先这里是一个重框卡片
（`render::table::card`，共享表格引擎的第三个消费者），框退役的原因：

* 全屏最重的线扛着最弱的内容（版本号、dim 文字），而品牌大字反而更轻；
* 框里的分隔空行看起来像"数据缺了一行"；
* 同一屏上还有 composer 的圆角框 —— 两种框语言互相解释不清。

现在结构靠**一条分节线**（`welcome::RULE` 画满块宽）：线上是"这是什么"（身份），
线下是"你能做什么"（键位 + tip + 入口），线下面紧贴键位（像表头）。线同时也是这块
文字的右缘 —— 块宽 = `max(大字宽, 键位行 / tip / 入口里最宽的一行)`，所以 2x 档是
46 列、1x 档跟着内容走。

**空气在块内**（`ui::welcome::identity_cluster` / `action_rows`）：词标下面一格空把身份
从大字上脱开，身份下面一格空把分节线从字里救出来。改前这六行字是零间隙的（分节线被上下
两行字夹住，读成「事实行」的下划线），而块外全是空气 —— 这一格空气来自**合并的身份行**，
不来自屏幕。

* **身份行**（`identity_line`）= 版本 + commit + 会话事实：`wing · dev · <commit> ·
  2 skills · 1 rule`。三段同为「这个会话是什么」、同为 `dim`，分两行没有任何好处。
  窄档从**尾巴整段**丢（先 `1 rule`、再 `2 skills`），丢一段仍是完整的身份，拦腰切一刀
  只会得到 `2 skil…`；放不下整段时也不许把块撑宽（80 列终端上 78 → 80 会把输入卡也
  拉宽，所以块宽只由操作簇与大字定）。事实缺席（0/0 / 老网关）时只留品牌 + 版本，
  行数不变 —— header 高度仍不随 sync 变化。
* **大字两档**（`wordmark::Scale`）：半格像素只能**整数倍**放大，所以是 1x（23 列 × 3 行）
  与 2x（46 列 × 5 行，每个源像素画成 2×2 —— 像素仍是正方的）。`scale_for(信息列宽)`
  放得下 46 列就用 2x，否则 1x。80 列终端的信息列只有 38 列，因此维持 1x。
* **寄存器**（谁亮谁暗）：身份（版本 / 事实）/ 入口 / 动作 = `dim`；按键与 **tip 正文**
  = `tool_result`（比 dim 亮一档，先看见敲什么）；`/命令` = `accent`（命令是唯一可以
  照着敲的东西，与 popup / 行内代码 / workdir 同一套约定；输入卡的 `❯`、粘贴 / 图片 chip、
  品牌图形与 spinner 另算 —— 见 [tui-input.md](tui-input.md) 的 composer 一节）。开屏上
  **最亮的文字止于 `tool_result` 一档**：键帽、键位行与输入卡的邀请句同档 ——这一屏的
  任务确实是让人知道往哪敲，但那由**形**说（框 + 键帽 + 提示句），不由正文墨说：占位句
  提到 `text` 会让空输入卡读成「已经有内容了」（见 tui-input.md 的 composer 一节）。
* **色块只在 2x 档**：键位行的每个键是一块键帽（`surface` 底 + `tool_result` 墨，左右
  各一格内边距），`Tip` 那枚标签**走同一档**——提示是用来读的，不是按钮：名牌里
  `accent` 只属于能照着敲的命令（`/tips`、`/`），没有一块 `accent` 的底。
  1x 档保持纯文本：那一档的块宽由内容决定，加宽的键位行（40 列）在那里比
  80 列终端的信息列（38）还宽；2x 档的块宽被大字钉死在 46，加宽的行不动几何
  （键帽行 38 → 40 列，最宽的 tip 5 → 6 列前缀 = 42，都还在 46 内）。键帽之间
  **不放 `·`**：块自己就是分隔。宽度 / 内边距降级 / 明暗两套底色与退路只有一份实现
  （`ui::chip`；消费方：本名牌的键帽与 `Tip` 标签、状态栏的 pin 星标与模型段、输入卡空草稿时顶栏
  右端那枚 `Enter` 键帽 —— 它旁边的动词同样是 dim，见 [tui-input.md](tui-input.md) 的 composer 一节）。
* **块的底与墨**（`ui::chip`）：**底**要过两道闸门 —— 不是 `reset`（那是终端默认
  底色）、离纸面 ≥ 1.2:1（看得出是一块）；**墨**按它压在哪里挑 —— 有底时强调档的纸色墨
  要过 3:1（控件线），过不了就换正文色（面留着、字换掉），没底时纸色墨等于写在纸面上，
  直接退正文色。最后兜一次：墨压在挑中的面上仍读不出，就连底一起不要。任何退路都不改
  宽度与内边距。亮色终端上 `surface` 与白纸只有 1.19:1，正是过不了「离纸面 1.2:1」，
  所以键帽的底在那里往 `text` 压 8%（1.38:1）——墨的交界在 9.6% 附近，8% 留了余量；
  命名色的 `surface` 不压（跟终端主题走，与 `config::stretch` 同一条规矩），方向不对
  （`text` 比 `surface` 还亮）也不压。`reset` 槽：前景（`text` / `tool_result` / 强调档
  的墨）按"终端默认前景"估（= 纸面的反面），背景（`surface` / `accent`）按"纸面本身"
  处理，所以 `surface: reset` 意味着既没有纸色可画、也没有纸色可作墨 —— 强调档退回正文色。
* **降级只丢尾巴**：一行一条、永不折行（折行会把下面的一切推下去）。80 列终端
  （信息列 38）里键位行与入口行整行放得下；最宽的 tip（池子上限 36 + `Tip  `
  5 = 41）丢尾巴，由 `/tips` 兜底。`the_nameplate_degrades_by_losing_the_tip_tail_never_by_wrapping`
  钉住这条线（键位 / 入口行文案变长会红，逼一次产品决定）。
  身份行不按列切，走的是**整段**丢（`the_identity_row_never_widens_the_block` 钉五个块宽）；
  `the_two_x_nameplate_needs_no_elision` 钉 2x 档的操作簇整行放得下。身份行能留几段
  跟着**品牌段的宽度**走（`dev` 20 列 / 发版 `v0.x.y` 更长），所以那条测试按整句自己的宽度
  判「放得下才要求整句都在」，不写死品牌宽度。

行数：1x 档 3 + 7 = 10 行，2x 档 5 + 7 = 12 行（名牌 = 空气 / 身份 / 空气 / 分节线 /
键位 / tip / 入口），都 ≤ `ART_TERM_ROWS`（13）；Full 档右列在海鸥盒子里竖直居中，
**竖直居中的余数行给上方**（`.div_ceil`）：两档的大字首行因此留在**原位**（2x 盒内第 1 行、
1x 第 2 行 —— 与名牌加空气之前取整到的地方相同），品牌锁合不动；向下取整会把整列上移一行。
代价是名牌末行与海鸥的脚共用盒底那一行。Compact 档没有海鸥盒，文字列就是整块 —— 名牌多一格空
会让 header 高一格，`splash_pad` 的余量少一格、整块上移一格（输入卡不动；小视口的边界也
跟着紧一格：40×15 起装不下开屏版式，40×16 起正常）。两份表单的高度天花板钉在
`the_info_column_never_overflows_the_art_box`（超了是整行静默消失）。

## 版面：空会话是一屏开屏

开屏不是一个"贴在顶部的 header"，而是**一块**：牌子 + 输入卡。位置由三处分工决定：

* `ui::welcome::Viewport { width, empty }` —— 内容侧：宽度决定档位，`empty` 决定
  "水平居中"还是"左对齐 + 一格留白"。两者都进 `needs_rebuild` 的键。
* `ui::welcome::splash_pad(screen_h, block_h, reserved)` —— 竖直位置：把「牌子 +
  一格间隔 + 输入卡」当一个整体放在**光学中心**（上方空气 = 余量 × 45%，上面少于
  下面）。`reserved` 用**基线**（单行输入卡 + 间隔），弹层与草稿长大不进这个账 ——
  否则用户每敲一个 `/` 整块都会往上跳几行。
* `app::frame_layout` —— 排版：开屏版式是
  `status | 空气 | 牌子(= chat band) | 间隔 | 输入卡 | 空气`，输入卡与牌子**同宽同列**
  （取 `Welcome::block_width()`，下限 48 列、上限整宽），命令弹层在开屏里是**浮层**
  （挂在输入卡下面、盖住空气，不占排版空间 —— 它不推动任何东西）；矮终端装不下
  （`1 + 牌子 + 1 + 输入卡 + 2 > 屏高`）时退回会话版式。

弹层能用的高度就是输入卡下面那几行（开屏尤其短），而列表的**滚动窗口跟着矩形走**：
`ui::popup::selection::visible_window` 取 `min(策略窗口, 装得下的条数)` 并把窗口挪到
包住选中项 —— 否则上下键走到末尾时高亮的那一条会落在画不出来的半截里（看得见列表在
动，看不见它停在哪）。

有消息之后开屏退位：`ChatView::is_empty()`（含排队中的消息）翻 false，输入卡钉回
底部、牌子回到 transcript 顶部（一格留白、左对齐），从此跟消息一起滚走。开屏时
chat band 只有牌子那么高，而且**不减滚动条 gutter**（空会话没有可滚的内容，也没有
滚动条）—— 所以 40 列的终端在开屏时拿到的是满 40 列。

**档位表**（内容宽：开屏 = 终端宽，会话里 = 终端宽 − 滚动条 gutter 2；Full 档会给
海鸥 + 间隔留 40 列）。阶梯**不单调**，这张表就是契约
（`the_width_ladder_is_the_recorded_one` 逐点钉住）：

| 内容宽 | 档位 | 信息列 | 形态 |
|---|---|---|---|
| ≤ 39 | Minimal | — | 一行 `wing` + 版本 |
| 40–73 | Compact | 39–72 | 无海鸥；1x 大字（信息列 < 46）/ 2x 从 47 起 + 分节线 |
| 74–85 | Full | 34–45 | 海鸥 + 1x 大字 + 分节线 |
| ≥ 86 | Full | ≥ 46 | 海鸥 + 2x 大字 + 分节线 |

注意 73 → 74 那一格：海鸥一出现就吃掉 40 列，信息列掉回 34，所以 76–86 列的终端
（80 列在内）反而拿不到 2x。这是既定优先级的代价 —— 「80 列必须落在整块档」
（`FULL_MIN` 的注释）且「海鸥不能让出去」，两条都不可破；把 2x 的门槛压到 38 列就得
牺牲别的（缩字号 / 裁字形 / 挤间隔），都不划算。框退役之后，窄档不再有"上框就要
折尾"的两难：分节线不占列，40 列起就能画。

## 重绘成本契约

海鸥是**常驻 idle 循环**，但只在欢迎屏真的在视口里时才走时钟：

* `ChatView::header_in_view()`（`scroll_offset < header_lines.len()`）是门控信号；
* 滚出视口 → `needs_rebuild` / `next_frame` 全部短路，run loop 的 select 臂停摆；
* 滚回顶部看历史 → 动作自然续上；
* 开屏扫光（wordmark 上那道）2.4s 后定格 —— 扫光期**逐帧**排 tick（~25fps），
  扫光**结束那一刻也要重建一次**（否则最后一帧的高光会留在屏上）；
* 定格之后 idle 循环以**实测 ~2.4 次/秒**唤醒（四平面并行），其中 ~99% 会真的
  改变姿态、各值一次"牌子 + 空气"的重绘。相比"滚出视口即 0"，这是常驻动画的代价，
  刻意如此（用户要的是 dsh 那种"活着"的欢迎屏）。

改这块时别破坏这条契约：看不见的东西不花钱，是 idle 循环能被接受的前提。

**首屏预算**：牌子本身 14 行（海鸥盒子 13 + 尾部一格）。空会话时它停在视口光学
中心、输入卡紧贴其下（`splash_pad` + `frame_layout`）—— 一屏里牌子之外本来就只有
空气，所以"预算"这条线只在**有消息**之后才真正生效（那时 header 退回顶对齐，
1 + 14 行）。
右列在海鸥盒子里的高度按档位变（2x + 名牌 12 行、1x + 名牌 10 行，竖直居中），盒子的
13 行与总高不受影响；Compact 档没有海鸥，总高就是"大字 + 名牌 + 尾部一格"（名牌多出来
的那一格空因此让 header 高一格 —— 开屏的 `splash_pad` 会把整块重新摆到光学中心，
输入卡的位置不变）。

## 品牌资产（README 页头 / 社交预览）

`assets/` 里的三份 SVG **不是手画的**，是 `cargo run -p wing --example export_logo`
从同一份数据导出的：网格读 `ui::welcome::art`（终端渲染的那几个网格），渐变读
`ui::welcome::wordmark::column_color`（终端那套渐变）—— 所以改画之后重跑一次，
README 与真机不会漂移。

| 文件 | 用途 |
|------|------|
| `assets/banner-dark.svg` / `banner-light.svg` | README 页头横版 lockup（`<picture>` 按 `prefers-color-scheme` 切） |
| `assets/gull.svg` | 站姿 mascot 单只（docs / 图标底稿） |
| `assets/social-preview.png` | 1280×640 仓库社交预览（Settings → Social preview） |

两条经验值得写下来：

* **大字按 2 倍像素画**（`WORDMARK_PIX`）。1px 笔画的 5 行字体放大到 3 倍以上，
  笔画之间的空隙会一起放大，字母开始读成虚线 —— 2 倍是散架的临界点。
* 社交预览 PNG 需要浏览器：`banner-dark.svg` 贴进一个 1280×640 的深色页面，
  headless Chrome `--screenshot --window-size=1280,640` 截一张即可（页面里的
  `<img>` 用相对路径时，包装页要放在 `assets/` 里，否则图加载不到）。

## 改画 / 预览的创作期工作流

帧数据是**定稿导出**，不是运行期生成：创作期用一个矢量光栅器（椭圆 / 胶囊 /
多边形 / 扫掠翼 → 4×4 超采样 → 硬边量化 → 外部 flood-fill 描边）画鸟，导出成
字母网格贴进 `art.rs`。改画的步骤：

1. 改形状参数，导出网格，渲染成 HTML（半格真宽高比 + 像素放大两视图）；
2. headless Chrome 截图（`--force-device-scale-factor=2`，长边 ≤1568px）；
3. `ReadImage` 看截图，改，循环 —— 像素画的细节（翼厚、喙角、描边脏不脏）
   只有看见才判得出来；
4. 定稿后把网格贴进 `art.rs`，跑 `cargo run -p wing --example welcome_preview`
   核对生产渲染与创作期一致（`--working` 看飞行态，`--ms` 落在某个动作帧）。

描边只加在**外部**透明像素上（边界 flood-fill）：形状之间 AA 缝隙留下的内部洞
不描边，否则满身麻点 —— 这是光栅器里最容易回退的一条。

改**整块**（状态栏 + 牌子 + 输入卡，连同光学中心与块宽）用
`cargo run -p wing --example splash_preview`：它走真 `App::draw`，一条命令给出
ANSI / `--plain` / `--html` 三种产物，`--preset` 过明暗、`--phase` 停在扫光的某一帧。
几何回归由 `app::tests::splash_frame` 的整屏指纹兜底（牌子的绝对位置、分节线长度、
输入卡边框行）—— 故意改版式常量时要一起更新那份断言。
